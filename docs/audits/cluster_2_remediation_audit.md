# 🛡️ Architectural Red-Teaming Audit: cluster_2_code_remediation.patch
**Audit Status**: `REJECTED` | **Model**: `deepseek-flash` | **Confidence**: `0.86` | **Timestamp**: `2026-11-04T15:50:51.647598+00:00`

## Executive Summary
The diff is a large security-remediation sweep (HMAC-signed Council Gate artifacts, O_NOFOLLOW review reads, atomic trust DB/lockfiles, Unicode-adversarial IPI scanning, bounded stdin). The intent is correct but the implementation contains blocking defects. The HMAC trust model is circular: the producer auto-provisions the signing key at ~/.gemini/config/omni_audit.key under the same UID that runs the verifier and the agent, so any prompt-injected process can mint a validly signed APPROVED artifact; the signature proves nothing beyond 'someone with the key signed'. The Windows key-path containment check uses raw str.startswith without a separator boundary, and permits tempfile.gettempdir() as a valid key location. The POSIX key-permission gate (0o077) locks out every pre-existing key file after upgrade with no migration. canonical_workspace_hash was switched MD5->SHA-256 with the idempotency guard removed and zero migration of omni_memory.db partitions, silently orphaning recall for all existing installs. The new heartbeat thread swallows all exceptions with 'except Exception: pass', guaranteeing the lockfile goes stale and is reclaimed by a second instance — the exact split-brain VULN-LG-001 claims to fix. The shipped test suite mutates real production telemetry (omni_memory.db, last_activation.json) and contains redaction placeholders that make several assertions unsatisfiable. Not mergeable as-is.

## 2. Top Critical Architectural Vulnerabilities (5 identified)
### 1. [CRITICAL] VULN-001: HMAC Council Gate key is self-provisionable by the same UID as the verifier — signature provides no trust separation
**Description**: scripts/memory_utils.py get_audit_hmac_key(auto_provision=True) generates a random key at ~/.gemini/config/omni_audit.key the first time sign_audit_meta() is called. consult_critic.py (the producer) and hook_runner.py (the verifier) both run as the interactive user, and the agent that a prompt injection controls also runs as that user and can invoke scripts/consult_critic.py directly. There is no privilege boundary, no code-signing of the producer, no out-of-band key exchange. Any process able to write ~/.gemini/config/ (or simply execute the critic script) can produce a byte-identical valid HMAC over an APPROVED verdict. The entire VULN-201 remediation therefore reduces to a checksum with a well-known key location, and is trivially defeated by the primary threat model (untrusted workspace content driving the agent).
**Remediation**: `Move signing off-host or behind a privilege boundary the agent cannot invoke directly (e.g., OS keyring with per-process access control, a separate service account, or a hardware/TPM-backed key with an explicit user-presence gate). At minimum, require producer keys to be manually provisioned out-of-band (auto_provision must never be reachable from a script the agent can call), record the producer identity in the signed payload, and refuse to auto-provision on any host where a key has never been operator-approved.`

### 2. [CRITICAL] VULN-002: Windows key-file path containment uses raw startswith without separator — sibling-directory key substitution
**Description**: memory_utils._verify_key_file_security() on Windows checks `key_real.startswith(home_real) or key_real.startswith(temp_real)` using os.path.normcase(os.path.realpath(...)) string prefixes. Prefix matching without a trailing separator treats /Users/bob as a prefix of /Users/bobby, so a key file resolved under a sibling directory is accepted as 'inside the user profile tree'. Additionally, allowing tempfile.gettempdir() as a valid key location means any process able to write %TEMP% can plant a key that satisfies the containment test on machines where the key path is redirected. The GetNamedSecurityInfoW call requests OWNER_SECURITY_INFORMATION (1) only, then discards the SID — the claimed DACL/ownership validation validates nothing.
**Remediation**: `Use os.path.commonpath([key_real, home_real]) == home_real (with both realpath+normcase) instead of startswith, and do the same for temp. Drop tempfile.gettempdir() entirely as an allowed location. Either actually validate the DACL (request DACL_SECURITY_INFORMATION and compare against the current user SID, rejecting any ACE granting write to non-admins) or remove the call and document that Windows ownership is not enforced.`

### 3. [CRITICAL] VULN-003: canonical_workspace_hash MD5->SHA-256 switch with idempotency guard removed and no omni_memory.db migration
**Description**: memory_utils.canonical_workspace_hash() now returns a 64-char SHA-256 and the previous idempotency short-circuit (`if is_valid_hex_hash(path, length=32): return path.lower()`) was deleted. hook_runner.process_hook() writes l1_staging_log.workspace_hash and memory partition keys using this function, and consult_critic/hook_runner also derive the audit workspace_hash from it. Every existing row in omni_memory.db is keyed by the old 32-char MD5; after upgrade those partitions become unreachable — JIT skill recall, proven_traces, and tier assessment silently return empty for all pre-existing installs, with no error surfaced. The diff adds a legacy-MD5 dual-read only inside verify_critic_artifact; nothing migrates the database. Separately, removing the idempotency guard means any caller that previously passed an already-hashed value now double-hashes it, producing a third, unrelated partition key.
**Remediation**: `Ship an explicit migration: either an ALTER+UPDATE migration that recomputes workspace_hash for all rows under a versioned schema bump, or a dual-key read path (query both MD5 and SHA-256 keys and merge) for at least one release. Keep a separate `canonical_workspace_key()` used for hashing and do not overload canonical_workspace_hash with idempotency semantics. Add a test that seeds an MD5-keyed row and asserts recall still works post-upgrade.`

### 4. [HIGH] VULN-004: POSIX key permission gate (st_mode & 0o077) rejects all pre-existing key files — hard lockout after upgrade
**Description**: _verify_key_file_security() rejects any key file where (st.st_mode & 0o077) != 0, returning False, which makes get_audit_hmac_key() return None, which makes verify_audit_meta() return False for every artifact. Any key file created by a prior version, by a user with umask 022, or by a manual `echo $KEY > ~/.gemini/config/omni_audit.key` will be 0644 and will hard-fail. Because verifiers never auto-provision, the system fails closed to a total functional lockout: every Council Gate review returns UNREVIEWED with no diagnostic surfaced to the user beyond a persist_diag line. There is no migration, no self-heal on the verifier side, and no user-facing remediation message.
**Remediation**: `On verifier path, attempt a best-effort chmod to 0600 before rejecting (or warn-and-accept-owner-only with an explicit diagnostic). Emit a single actionable stderr line naming the exact path and the required mode. Only hard-fail when the file is group/other *writable* (0o022), not merely readable.`

### 5. [HIGH] VULN-005: Heartbeat thread swallows all exceptions and continues — guarantees stale-reclaim split-brain on a live process
**Description**: lifecycle_guard._start_heartbeat()._beat() wraps the entire CAS body in `except Exception: pass` inside the while loop. Any persistent failure (mutex timeout, transient OSError from os.replace, filesystem full during _atomic_write_payload, json decode of a concurrently replaced file) is silently discarded and the loop continues. The lockfile heartbeat therefore stops advancing while the owning process is fully alive. acquire_lock() on a second instance observes is_alive=True but is_heartbeat_stale=True and reclaims the lock — the exact double-acquire split-brain that VULN-LG-001 is claimed to eliminate. Two instances then both believe they own exclusive resources (SQLite writers, consolidator). This also directly violates the stated 'Never swallow exceptions' invariant.
**Remediation**: `Count consecutive heartbeat failures; after N consecutive failures (e.g. 2), set _stop_event, emit a diagnostic with the exception, and mark the guard as degraded so callers can shut down cleanly rather than losing the lock silently. Never `pass` on an exception in the heartbeat path; at minimum call persist_diag with the exception and a counter.`

## 3. Concurrency, Race Condition & Mutex Hazards (5 identified)
- **Resource**: `~/.gemini/run/{name}.mutex (ProcessMutex)` | **Hazard**: Symlink / permission race — open(self.path, 'a+b') follows symlinks with no O_NOFOLLOW and default umask mode | **Mitigation**: Open with os.open(path, os.O_RDWR|os.O_CREAT|os.O_NOFOLLOW, 0o600) and wrap the fd with os.fdopen. Reject if the path exists as a non-regular file. Same fix required for TrustFileLock.lock_path, which has the identical pattern.
- **Resource**: `scripts/last_activation.json` | **Hazard**: Lost update — atomic os.replace gives no serialization; N concurrent hook invocations all fsync and replace, last writer wins | **Mitigation**: Accept the loss explicitly (telemetry) or guard the replace with TrustFileLock. Document the semantics. Do not claim 'atomic' as if it implied serialization.
- **Resource**: `scripts/activations_history.jsonl` | **Hazard**: Silent audit-trail loss — TrustFileLock(timeout=0.2) raises TimeoutError under contention, caught by 'except Exception as lock_err: persist_diag(...)', entry discarded | **Mitigation**: Increase timeout budget off the hot path, or append to a per-PID shard and merge lazily. Audit trail entries must not be dropped silently; on overflow write to a fallback shard rather than discarding.
- **Resource**: `omni_memory.db` | **Hazard**: Hot-path lock acquisition — 'PRAGMA journal_mode = WAL' is executed on every hook invocation and requires an exclusive latch; sqlite3.connect(timeout=1.0) can block the hook for up to 1s against a stated 25ms SLA | **Mitigation**: Set journal_mode WAL once at DB creation/migration time, not per invocation. Use timeout=0.05-0.1 for the staging insert and fail-open (skip telemetry) rather than blocking the PreInvocation hook.
- **Resource**: `{name}.pid lockfile` | **Hazard**: PID reuse — is_process_alive(pid) returns True for a recycled PID, so a stale lock is never reclaimed within max(stale_timeout_sec, heartbeat_interval*3) | **Mitigation**: Store process start time (from /proc/<pid>/stat on Linux, GetProcessTimes on Windows) in the payload and compare it alongside the PID; treat a mismatch as dead regardless of liveness.

## 4. Defensive Failure Scenarios & Edge Cases (5 verified)
### 1. A review artifact whose signed JSON value legitimately contains the sequence '-->' (e.g. a target_file or model string).
- **Consequence**: The non-greedy regex r'<!--\s*OMNI_AUDIT_META:\s*([\s\S]*?)\s*-->' terminates the capture at the first '-->', json.loads fails, the candidate is skipped, and the verdict silently degrades to UNREVIEWED with no diagnostic.
- **Mitigation**: Parse the header by locating the first '\n' after the OMNI_AUDIT_META marker and decoding the JSON from a fixed-length prefix, or require base64-encoded JSON in the comment. Emit an explicit diagnostic when a candidate's metadata fails to parse.

### 2. consult_critic.py is invoked from /tmp (or a CI workspace root) against a target whose ancestors contain neither .git nor GEMINI.md.
- **Consequence**: find_workspace_root() falls through to os.path.realpath(os.getcwd()) and the artifact is signed with hash(/tmp). Two unrelated workspaces audited from the same cwd produce an identical workspace_hash, re-opening the cross-workspace replay that VULN-001 was meant to close.
- **Mitigation**: Fail closed: if no .git/GEMINI.md is found, refuse to sign and require an explicit --workspace. Never silently substitute cwd for the target's workspace.

### 3. A workspace directory contains a 'specs' entry that is a symlink to an unrelated tree, or an attacker-supplied directory with tens of thousands of entries.
- **Consequence**: os.listdir(specs_dir)[:15] slices after a full listdir (unbounded allocation on huge/remote FS), and os.walk is replaced by a manual two-level scan that follows symlinked directories, pulling CRITIC_REVIEW.md from outside the workspace.
- **Mitigation**: Use os.scandir with an explicit counter and break at 15, check entry.is_symlink() and skip, and add os.path.commonpath containment assertions for every candidate path before opening.

### 4. redact_secrets() is called with a dict/list (now supported) and the result flows into a caller that treats the return as str, e.g. safe_user_input[:150]. The signature is still annotated Optional[str].
- **Consequence**: A future call site passing a dict returns a dict, and slicing/string-concat raises TypeError inside process_hook, which is caught by the outer 'except Exception' and converted into an empty injectSteps — a silent pre-flight failure.
- **Mitigation**: Add a separate typed function redact_json_object() for structural payloads and keep redact_secrets() -> Optional[str] strict. Update the annotation and add an isinstance guard that raises a loud TypeError.

### 5. The committed test suite is executed on a developer machine or CI runner with an existing omni_memory.db / last_activation.json.
- **Consequence**: TestHookRunnerRemediation.test_process_hook_updates_last_activation_cleanly calls the real hook_runner.process_hook() with no monkeypatching, overwriting the developer's production last_activation.json and inserting rows into the repository's omni_memory.db; tests also depend on '[REDACTED_*]' placeholders (test_preflight_redacts_credentials, test_redact_secrets_recursive_dict_list) that make assertNotIn/assertIn unsatisfiable — the suite cannot pass as committed.
- **Mitigation**: Refactor process_hook to accept injected paths (activation_path, history_path, db_path) or monkeypatch hook_runner.LAST_ACTIVATION_PATH / ACTIVATIONS_HISTORY_PATH to a TemporaryDirectory in setUp. Replace scrubbed placeholder assertions with synthetically generated key-shaped strings built at test time (e.g. 'sk-' + secrets.token_hex(24)) so the redaction regex is genuinely exercised.

## 5. Prescriptive Remediation Directives (9 items)
- REDESIGN the Council Gate trust model before merge: the signing key must not be provisionable by any process the agent can invoke. Either move signing off-host, require explicit operator provisioning of ~/.gemini/config/omni_audit.key with a documented out-of-band step, or drop the HMAC and replace it with an integrity check that is honestly labelled as tamper-evidence rather than authenticity.
- REPLACE every `str.startswith(path_prefix)` containment test with os.path.commonpath() equality. Locations affected: memory_utils._verify_key_file_security (Windows home/temp checks). Add a unit test using /home/user vs /home/user_evil.
- SHIP a schema-versioned migration for omni_memory.db when changing canonical_workspace_hash from MD5 to SHA-256, plus a dual-key read window. Restore a dedicated hashing function; do not overload canonical_workspace_hash with idempotency semantics that were silently removed.
- REMOVE all `except Exception: pass` occurrences introduced in this diff (lifecycle_guard._beat, release_lock, acquire_lock reclaim path, hook_runner artifact scan, history rotation). Each must either persist_diag with the exception type and context, or propagate. The diff's own docstring claims 'Never swallow exceptions' — enforce it.
- ENFORCE os.O_NOFOLLOW + 0o600 on every file opened for locking or creation (ProcessMutex, TrustFileLock, key file, last_activation tmp, history). Add an S_ISREG check after fstat on the mutex fd.
- DO NOT claim a 25ms PreInvocation SLA while executing os.fsync, PRAGMA journal_mode=WAL, and a cross-process file lock on the hot path. Instrument process_hook with perf_counter and add a regression test asserting p99 under the stated budget on a cold page cache.
- ISOLATE the test suite from production state: inject or monkeypatch LAST_ACTIVATION_PATH, ACTIVATIONS_HISTORY_PATH and the SQLite path per test. Remove or regenerate all [REDACTED_*] literals so every redaction assertion is actually satisfied by a real match.
- ADD a fail-closed diagnostic path for every silent UNREVIEWED outcome in verify_critic_artifact (missing signature, key unavailable, metadata parse failure, wrong workspace_hash) — reuse the stale_reason field consistently across all branches, including the inline branch which currently sets stale_reason but leaves best_verdict as UNREVIEWED while other branches return STALE_REVIEW.
- REPLACE os.listdir(...)[:15] with os.scandir + explicit counter + entry.is_symlink() rejection in verify_critic_artifact, and add os.path.commonpath containment assertions on every candidate path before os.open.
